# 人写稿的写法（朱雀/AI 检测应对）

写稿前读。这份文件是 2026-09 八轮朱雀检测反复回到 100% 之后的总结。2026-09-12 接上朱雀 API 之后，下面"实测结论"一节是拿真实分数做对照实验得出的，优先级高于后面所有靠推测写的规则。

## 实测结论（2026-09-12，朱雀 API，同一段文字做变量对照）

闸门是 `scripts/zhuque-check.mjs`：**硬线是人 100% 且每块 label=0**（softmax < 0.1 是参考值，见下一节第二轮实测）。纯人写文本（whisper 转写、弹幕）实测 softmax 0.000–0.05，这是天花板。检测器按约 300 字分块打分，不按段落；末尾 `---` 之后的交付说明脚本会自动跳过。

1. **英文直引号 `"` 是强 AI 特征。**同一段字，直引号 softmax 0.584（疑似 100%），换成中文弯引号 `“”` 变 0.201（人 100%）。整篇 v1 只换引号，疑似 62% → 0%。原样稿只换引号，71% → 41%。前八轮全是直引号。写完必跑 `scripts/fix-quotes.mjs`。
2. **"引号原话 + 记者式串词"这个格式本身是疑似。**"弹幕炸了，一半在问……另一半在科普""库特菌是大坝本地人。""我数了十三条"这种串词，配上一句一引号，落在 0.25–0.58。同样内容改成**口语串**：原话不加引号直接揉进逗号长句，中间夹"我当时没反应过来小面包是啥""这个我没看到""我都懒得看""得有二十多遍吧"这类碎念，落到 0.025–0.07。整篇 v3 按这个写法，softmax 0.577 → 0.045。
3. **只删对称结构和计数没用。**0.584 → 0.535，标签没变。前七轮就是在做这个。
4. **纯实录（时间戳 + 原话 + 弹幕）是人（0.047）。**但那不是稿子，是字幕。它说明素材本身没问题，问题全在串词。
5. 素材复用率（text-stats --raw）在 v3/v4 只有 16–17% 但检测已经全过，所以"40% 复用率"这条硬规则取消，改为参考值。真正管用的是：原话要多、串词要像说话。

**写完之后的循环（最多 4 轮，每轮约 2000 token 额度）：**

```text
fix-quotes.mjs → zhuque-check.mjs → 没到目标：找 conf 最高的那块，按"口语串"整块重写（不改词、不删句）→ 再测 → 记 detection-log.md
```

## 实测结论（2026-09-12 第二轮：可读性 vs 分数）

第一轮压到 softmax 0.045 的那种稿子，用户的反馈是"不像公众号文章，缺少可读性"：引号全删、每段四五行不断句的逗号流，读者分不清是主播在说、弹幕在刷还是作者在判断。这一轮拿贱徐稿做了 6 个单变量版本（v5–v10，见 detection-log.md），结论：

1. **文末"待审/来源/授权"那段才是整篇分数最大的单一来源。**它是公文腔模板，单独成块稳定在 0.43–0.54，贱徐 v2–v5 每一版最高的那块都是它，不是正文。它本来也不该进可发布正文（见 editorial-memory 的发布格式规则），现在 `zhuque-check.mjs` 和 `text-stats.mjs` 都会把末尾 `---` 之后的交付说明切掉再测。同一篇稿子只是不测这段，0.425 → 0.142。**交付说明一律写在正文末尾的 `---` 之后。**
2. **关键处加弯引号很便宜。**3 处原话加 `“”`：0.142 → 0.164，仍然人 100%、每块都判人。可读性收益远大于这 0.02。禁的是"一句一引号连排 + 记者式串词"，不是引号本身。
3. **把逗号长句拆成句号短句会涨分。**同样的开头内容，逗号串是 0.204，拆成"…做完了。/ 视频第一句就是这个。/ 屏幕上…"之后是 0.330。中文口语的形状就是逗号串，句号切碎反而像模型。
4. **冒号引导、成对的短句金句、书面腔动词是涨分大户。**v6 只加了这三样（6 处"装备页：""撤离成功页："式冒号、"六个人，前后二十秒。/ 三十秒的窗，够了。"这种成对收尾、把"念"改成"话音还没落"这类写作腔），整篇 0.142 → 0.351，还掉出人 100%。
5. **短段落、空行、图前钩子不涨分。**v7 分了 31 段、段CV 0.81、9 个一行段，分数比 11 段的 v5 还低。可读性靠分段和空行拿，不靠句号。

**闸门改了：硬线是"人 100%，且每块 label=0"**（判疑似的阈值在 0.5 附近，块 conf 压到 0.35 以下就有余量）。**softmax < 0.1 降级成参考值**——实测它只有在整篇不加引号、不分段的情况下才拿得到，而那样的稿子用户不认。两者冲突时可读性优先，别再为了 0.05 的分差把稿子改回字幕流。

## 实测结论（2026-09-13 第三轮：公众号排版 vs 过检）

用户要求「排版清晰、能过风控」，并指认热门攻略站《三角洲攻略站》为参照。同稿（唐吉逐星者行动）做了多版单变量对照，结论：

**能过检的排版手段（便宜）：**
1. **分段 + 空行 + 图前钩子 + 一行段。**把 300 字逗号长串拆成 3–5 个段落，段内仍是逗号长句，人 100% 可保住（v9：softmax 0.245，最高块 0.389）。
2. **开口用 3–6 字钩子独立成段。**例如「爆干了三天。」后面再展开，像公众号折叠线前的第一眼。
3. **文末一句互动**（「你那边唐吉做了几次才进二阶段？」），不涨分。
4. **弯引号关键原话 2–5 处**，仍便宜。

**会把分打爆的「公众号排版」手段（贵，不要用）：**
1. **`##` 加粗小标题**（「找人先别急」「真正把人整疯的是次数」）——结构越像目录，分越高。v4/v5 加标题后疑似 41%–63%。
2. **圆点/编号列表**（`· 我做了两次…`）——列表块可单独判 AI（v7 列表段 conf 0.990）。
3. **`>` 引用框**放官方公告——公文腔，v4 最高块 0.565。
4. **全文加粗关键词/结论先行框**——与攻略站体例同源，整篇人 0%。
5. **把逗号长句拆成句号短句做「可读」**——v8 实测疑似 41%。可读性只能靠分段，不能靠拆句。
6. **完整攻略站体**（干员们好啊 + 结论清单 + 加粗小节 + 分条步骤 + 星标 CTA）：v7 人 0%、AI 23%、softmax 1.000。**不要为了像热门公众号去套这个骨架。**

**推荐交付公式（排版清晰 + 人 100%）：**
```text
短钩子开场 → 逗号长句段（2–4 行一段，空行分开）
→ 一行段做节奏（「难的是次数。」）
→ 图前一句钩子
→ 弯引号 2–3 处
→ 段内保持口语逗号串，绝不拆成句号短句
→ 文末短回忆 + 一句互动
→ --- 之后写待审/来源
```
若用户坚持要攻略站体例（小标题/分条/结论框），可另出「排版增强版」，并明说朱雀会掉到人 0%，默认不作为过检交付稿。

## 可读性：怎么让它像一篇公众号文章

分数低不等于能读。读者是在手机上看，一屏大概十行。下面这些实测几乎不涨分，可读性提升最大：

- **一段只讲一件事，两到四行就分段，段间空行。**不要一段塞五行还不断句。
- **段落长度仍然要不均匀。**大部分两三行，中间给一个两百字的长段（弹幕吵架、连着打好几队这种最合适），再撒几个一行段（"说完继续打。"）。
- **每张图前面留一句钩子。**图接在能跟画面对上的那句话后面，不要插在一段中间。图注只写画面上能核对的东西，不写感想。
- **谁在说话要一眼分得清。**主播原话、字幕、弹幕、作者判断混在一段里是最难读的。用"他接了句""字幕写着""弹幕在刷""我没试过"这类口语引导词起头，最关键的一两句原话直接上弯引号。
- **UI 数字挑着写。**结算页十几个字段别全抄，挑跟这篇有关的两三个（对局时间、击败干员数），剩下的交给图。
- **标题把冲突放在后半句。**"30秒6杀他真做完了，只是这局打在8月31号"——前半句给结果，后半句给反转。

## 视角：我们在直播间看着，不是在解说一条视频

2026-09-12 用户收口：稿子的"我"是当时在看的人，不是拿到一条投稿逐段讲解的解说。正文里一路"视频第一句""画面里""字幕写着""标题说"，读起来就是在复述别人的作品，人味全没了。

素材先分两类，这是这条规则的落点：

- **现场层，能进正文**：主播原话（转写）、弹幕、局内 UI 和局内画面——装备页、小地图、倒计时、成就弹窗、结算页、撤离页、击杀列表。这些是当时在直播间就能看见的东西。
- **投稿层，不进正文**：视频标题、后期字幕、简介、标签、发布日期、BV 号、封面、剪辑顺序、播放量。这些是录播发出来之后才有的，直播间里不存在。它们进文末 `---` 之后的交付说明，作为来源和核验记录。

具体写法：

- **不写这些词**：视频、这条视频、这条投稿、画面里、画面上、字幕写着、标题说、回放、播放、发布于、UP主、剪辑。
- **换成这些**：他、他这局、开局、出门前、麦上、弹幕、结算页、小地图、成就弹窗、撤离页。"视频第一句就是这个" → "他开口第一句就是这个"；"撤离成功页显示对局时间为 08-31 15:50" → "最下面那行小字是对局时间，08-31 15:50"。
- **后期字幕不能当他说的话。**字幕和原话对得上的（比如"六分钟四套""天才少年""可惜不是新赛季"转写里都有），直接用原话；只有字幕才有的（"轻轻松松拿下""咱往桥边一趴"），要么不写，要么在交付说明里注明来源是后期字幕。把后期字幕写成"他说"是事实错误。
- **标题里的话不是他的话。**"手拿把掐"这种是投稿标题的文案，不能写成"他嘴里那句手拿把掐"。
- **第一人称是观众，不是复述者。**可以写"我盯着弹幕看了半天""这波我没看清""我没试过"。不能写"我后来又拖回去看了一遍回放"——那既是解说视角，也多半是编的经历。
- **时间锚点用局内的，不用投稿的。**"8月31号下午三点五十那局"（结算页上的）能进正文；"9月4日发的"不进正文。

分数上这条不亏：贱徐稿从视频视角（v11，softmax 0.138）改成直播视角（v14，0.226），全篇仍是人 100%、每块 label=0，开头那块反而从 0.177 降到 0.115。涨的那部分在结尾块，跟视角无关。

## 先说清楚为什么改词没用

朱雀这类中文检测器看的不是某个词，而是整篇文本的统计形状：

- 句子长度是不是都差不多（AI 稿标准差很小，人写的忽长忽短）
- 段落长度是不是都差不多
- 每句话是不是都"完整、通顺、信息刚好"（人写的会有半句、废话、重复）
- 用词是不是每次都换同义词（AI 爱换词，人一个词用到底）
- 有没有只有在场的人才写得出来的细节
- 论证是不是对称的（正方、反方、我认为）

所以"删掉说实话、改掉不是而是、砍掉总结句"这种做法，删完之后剩下的是一篇更均匀、更短、更没人味的稿子，检测分反而回升。前七轮就是这么失败的。

正确方向只有一个：**不要在 AI 稿上改，要按人的流程重新写一遍。**

## 但光"重新写"还不够：字得真的来自人

2026-09-11 第八轮的教训：按上面的形状要求重写之后，朱雀分还是高。回头看那篇稿子，每个字都是模型生成的，碎句、跑题、语气词全是模型模仿出来的。检测器本质上是在判断"这些字是不是模型最顺手的那种排法"，模型再怎么模仿人，排出来的还是模型最顺手的字。形状指标能过，字的来源过不了。

所以从第八轮起加一条要求：**正文的字要尽量原样来自用户提供的人写素材。**`text-stats.mjs --raw 素材.md` 能量个大概（8 字以上完全相同的片段才算，转写是短句所以会偏低，参考用，不设硬线）。

人写素材指的是：

- 视频全文转写：`node scripts/fetch-video-text.mjs BV号`，不用登录就能拉全部弹幕（按时间排好、附刷得最多的前 15 条）；加 `--cookies-from-browser edge` 能拉 B 站字幕（就是主播原话）；没字幕的视频下音频跑 faster-whisper。这一步是默认的，每篇都做
- 用户自己看完直播后发来的语音条转文字、或者随手打的一段话（不改错字、不改语序）
- 用户和朋友聊这场比赛的聊天记录
- 主播直播里的逐字原话（口头禅、停顿、脏话打码，都保留）
- 弹幕原文
- 用户自己打这张图的真实经历，用用户自己的话

转写和弹幕解决的是"主播说了什么、观众当时在刷什么"，量大、逐字、带时间戳，样稿里只有 3 处原话就是因为没做这步。但它替不了用户的口述：主播的话是发生了什么，文章的看法还是得有个人在说。没有转写不开工；没有用户口述可以开工，但看法部分只能写短，写不出来的地方留白问用户。

模型在这个流程里的角色是：把用户的话按时间顺序摆好，中间补上核对过的数字、规则半句、图。**用户说过的话，能原样用就原样用，不润色、不缩句、不改成书面语。**用户那句话有语病、有重复，留着。

## 写的时候不要写"模型最顺手的句子"

即便是补的那部分字，也要避开模型最爱的排法。具体禁令：

- **原话不要"一句一引号"地排。**“你右边”“可惜了”“打不动他”这种连排是疑似。写成：地下通道，你右边，可惜了，打不动他。原话直接进逗号长句；全篇挑一到三句最关键的加弯引号（实测只涨 0.02，换来读者一眼看出谁在说话，值）。
- **不写记者式串词。**"弹幕炸了，一半在问……另一半在科普""我数了十三条""库特菌是大坝本地人。"这种交代事实的整齐句子是疑似。换成：弹幕已经开始刷还真是库特还真是库特，刷了十几条，中间夹着这里是地狱吗，我才想起来库特菌就是天天在大坝那个。
- **夹碎念。**"这个我没看到""我没核过，弹幕说的""我都懒得看""得有二十多遍吧""也可能就是随口一说"。一段至少一处。碎念必须是真的（没看到就是没看到），不能编经历。
- **句首不用连接词。**所以、因此、但是、不过、其实、而且、同时、此外、然而、这时候。人说话两句之间不搭桥，直接下一句。
- **不写解释句。**"这意味着""也就是说""说明了""关键在于""区别在于"，以及任何一句存在的目的只是解释上一句的句子，删掉，让上一句自己站着。
- **不写格言。**"活着带出来才是你的""考的是在不确定里做决定"，这种能单独发朋友圈的句子，全是模型的。人写东西不会顺手来一句金句。
- **不给每件事一个理由。**模型写"他没打，因为物资分权重高"。人写"他没打。"读者自己会想。
- **不用"打法很清楚""思路很明确"这类替读者总结的话。**
- **多用语气词收句。**吧、呢、啊、嘛、哈、诶、嗯。"他这局稳得有点过了吧。"不是每句，但一篇 900 字至少三四处。
- **选词选不那么顺的那个。**要写"撤离"，玩家嘴里是"带出来""跑了""润了"；要写"击杀"，是"做了""点了""干掉"；要写"队友"，是"随机排到的那个""他那个杰克"。模型第一个想到的书面词，换成玩家嘴里的那个。
- **数字不凑整、不解释。**"14分48秒，29发"直接写，不接"弹药充足"。
- **段落不按意思分。**模型一段一个意思。人一段里塞两件事，或者一件事写着写着换段了。可以在一句话中间换段。

## 写之前：只准备素材，不准备观点

先列一张素材单，全部是原始东西，不加任何判断：

```text
- 用户的口述/聊天记录原文（整段贴，不动一个字）
- 局数/地图/主播/随机队友 ID
- 游戏内时间点 + 当时 UI 数字（弹药、血量、倒计时、积分）
- 主播原话（逐字，包括口头禅、脏话可打码）
- 弹幕里刷得最多的一句
- 用户看到这里的第一反应（用户自己的话，不是模型替他想的）
- 用户自己在这张图死过的一次（真实的，没有就向用户要）
- 规则里跟这一幕直接相关的一条（不要整段规则）
```

素材单不进正文。它的作用是让写的时候手边全是具体东西，不用靠抽象词撑段落。素材单同时另存成 `素材.md`，写完拿它跑 `--raw`。

## 写的时候：像发语音条一样一口气写

打开素材单，假设对面是一个也看了直播的朋友，一次写完，不回头修。要点：

**开头直接从一个瞬间开始。** 不介绍背景，不说"最近的主播巅峰赛"。可以是主播的一句话、一个 UI 数字、一个弹幕。规则等需要用到的时候再插半句。

**句子长短要走极端。** 中文人写东西是拿逗号连很长一句的：

> 他这时候血也不满，弹匣里就剩十几发，旁边杰克还没开麦，弹幕全在刷让他走，结果他还蹲那摸血氧仪，我看着都急。

然后接一句三四个字的。

> 带出来了。

一段里最长的句子至少 50 字，最短的不超过 8 字。这是硬指标，写完用 `scripts/text-stats.mjs` 查。

**段落长度也要走极端。** 有一段七八行讲一波对枪，下一段一行。不要每段三行。

**一个词用到底。** 说"带出来"就一直说"带出来"，不要第二次换成"成功撤离"、第三次换成"完成提取"。AI 换词，人不换。

**允许写废话。** 一句没信息量的插话，比如"这局我其实没从头看"，"后面那段掉帧了没看清"，"我忘了是第几分钟"。这些是人写的痕迹，不要删。

**允许半途改口，但不要写成心路历程。** 可以是"我本来想说他怂，不对，是稳"，一句话内部改。不要"我一开始觉得……后来发现……"这种整齐的两段式醒悟。

**允许跑题一句再拉回。** "说到血氧仪，这赛季刷新率是不是改了，反正我最近三局没见过。回来说老飞宇。"

**观点要偏。** 不平衡。可以明确说"我觉得随机匹配这规则就是坑"，然后不给反方。或者反方只给一句"也有人觉得样本大更公平，行吧"。不要"两边都有道理"。

**主播原话直接贴。** 逐字，包括"嗯""诶""卧槽"。原话是最难伪造的人味。但不要一句一引号地排，揉进逗号长句里（见上面实测结论第 2 条）。

**结尾不总结。** 最后一段可以是：下一场什么时候、一句吐槽、一个没答的问题、或者干脆讲完最后一波就停。禁止"两局看下来我的感受是"。

## 写完之后：只做三件事

1. `node scripts/fix-quotes.mjs 稿子.md`，然后 `node scripts/zhuque-check.mjs 稿子.md --json 朱雀-vN.json`。没到硬线（人 100%、每块 label=0）就找 conf 最高的那块，按上面"口语串"的写法整块重写，再测。最多 4 轮。已经是人 100% 只是 softmax 还在 0.1 以上，不要为了压这个数去删引号、删分段——那是上一轮把稿子改成字幕流的原因。每一版另存（v1、v2……），不覆盖。脚本报没找到 key 就停在这一步：没有分数不迭代，稿子标"未检测"交付，让用户把 .env.example 复制成 .env 填 key。
2. 核对事实（地图名、时间、数字、原话），见 source-verification.md。转写来的原话在交付说明里标"自动转写，需听一遍核对"。凡是"我"的经历和反应，交付时列出来让用户确认，用户不认的删掉。
3. 每一版的 `zhuque-check --log` 和 `text-stats --log` 两行记进 `detection-log.md`，写清这版改了什么。分数变化就是下次的规则来源。

`text-stats.mjs` 现在是形状自检，不是闸门。检测过了但形状指标没过，以检测为准。

## 三种体裁的骨架

**看直播随手记**：一个瞬间，讲完就完。500–900 字。规则半句带过。不给结论。

**整局复盘**：常见观点一句开头 → 按局写（第几局、地图、队友）→ 每局挑一两波对枪写数字和原话 → 主播自己怎么说 → 我怎么看，一两句，不收束。1200–2000 字。

**版本体验**：我自己打了几局什么感觉 → 数字（改前改后）→ 跟直播里看到的对不对得上 → 还没想明白的地方。

争议选题不要单独成一种体裁。争议是从上面三种里长出来的，不是骨架。

## 对照：同一段的两种写法

AI 稿（前七轮的样子）：

> 老飞宇这局打得比较稳，搜到东西就往撤离点带。撤离倒计时27秒的时候还在摸血氧仪，队友小红帽老板和WawaDVO在旁边。最后带出来了。
>
> 物资分在这套积分里权重最高。你搜到好东西活着带出来，积分比硬刚清场两局高。所以他有些看起来不敢打的选择，算账之后其实是赚的。

人写的方向：

> 倒计时 27 秒他还在摸血氧仪。我数了一下旁边站着小红帽老板和 WawaDVO，三个人谁都没催，弹幕倒是急疯了，一屏"走啊走啊"。这赛季血氧仪我是一次没搜到过，不知道是不是我脸黑。
>
> 带出来了。
>
> 这个积分规则物资分最重，我后来翻了官方页才注意到，击杀分其实挺低的，你打两局清场可能还不如他这一趟摸出来的多。所以他前面几次看着像怂的地方，我现在觉得是算过账的，当然也可能他就是怂，我不知道。

后一段有长句、有碎句、有跑题、有不确定、有一个词重复用（摸），检测器看到的"形状"就不一样了。（示例里的弹幕内容和"我没搜到过"是为了演示句式编的，真写的时候这两处必须是真的。）

## 事实边界不变

人味不等于编。原话必须是原话，个人经历必须是真的（没有就问用户要），数字必须核对。跑题那句也不能编数据。
