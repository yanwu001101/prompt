# 三角洲公众号真实配图规范

## 真实素材硬规则

- 赛事复盘使用该场官方回放的真实帧；游戏攻略使用当前版本真实地图或用户/官方真实游戏截图。
- 不生成、重绘或用相似画面冒充真实比赛、选手、地图、掉落、枪械表现和局内画面。
- 不用宣传海报代替关键局内证据。海报可交代赛事背景，不能证明战术判断。
- **宣传图 ≠ 局内图（2026-09加严）**：官网 banner、赛季 KV、模式展示渲染、CG 截图、选手定妆照，一律不算局内证据图。局内图必须能看到游戏 HUD（小地图、血量/护甲、弹药、击杀播报、倒计时、资产/票数、赛制提示条至少其一）。没有 HUD 的"像游戏截图"的画面，按宣传图处理，禁止当作证据图使用。
- **主播赛/赛事稿配图底线**：正文引用的比赛规则、积分构成、赛果，优先配该赛事官方回放截帧或官方直播截图。如果只有宣传 KV 没有局内帧，正文里就不要出现"如图所示""画面显示"这类依赖图的表述；把图位空着并写明"待补官方回放截帧"，不要用宣传图凑数。
- **平台水印 vs 赛事 UI（2026-09加严）**：平台水印（B站/抖音/快手 logo、UP 主 ID 水印、直播平台台标）发布前用无痕 inpaint 去掉；赛事 UI（赛制提示条、WEEK/排名方式、倒计时、击杀播报、干员栏、小地图）必须保留，它们是证据。官方赛事台标/授权水印按授权要求处理，不自行去掉。
- 找不到可靠底图或关键帧时，继续查官方回放/镜像；仍找不到则向用户索取，不自制近似画面。索取时明确说明需要什么：赛事名、地图、局数、游戏内时间、要证明的判断。

## 从公开视频截局内帧（工作流）

官方直播回放和主播第一视角实录都可以作为局内图来源。操作步骤：

1. 用 B站搜索 API 找视频：`https://api.bilibili.com/x/web-interface/search/type?search_type=video&keyword=关键词`，优先选带「第一视角」「实录」「回放」标签、时长 10 分钟以上的稿件。
2. 用 `yt-dlp -f <format> --download-sections "*起-止"` 只下需要的片段（720P 通常够用），避免下整场。
3. 用 `ffmpeg -ss <时间> -i 片段 -frames:v 1 -q:v 2 输出.jpg` 按时间点抽帧。文件名用 `raw-a.jpg` 这类短名，避免和旧文件混淆。
4. 打开抽帧检查：必须有 HUD（小地图、队友栏、弹药、赛事 UI 至少其一）；CG 开场、转场动画、黑屏跳过。
5. **无痕去平台水印**（见下一节），保留赛事 UI。
6. 图注写明：视频标题、UP 主、BV 号、截帧时间点。不把处理后的图声称为官方原图。
7. 素材台账补上原始链接和授权提醒：公开可看 ≠ 可商用，正式发布前建议联系 UP 主或赛事官方确认。

工具依赖：`yt-dlp`、`ffmpeg`（便携版即可）、`opencv-python-headless`。Windows 下把 ffmpeg 的 bin 目录临时加入 PATH 再调用。

## 无痕去平台水印（OpenCV inpaint）

禁止用纯色块/模糊盖水印——边缘一眼假。正确做法是 cv2.inpaint：

```python
import cv2
import numpy as np

img = cv2.imread("raw.jpg")
mask = np.zeros(img.shape[:2], dtype=np.uint8)
# 只动左上角，x 严格 < 250，绝不碰中间指南针（x>280）
# 1) 左上 UID 文本条
mask[0:16, 0:250] = 255
# 2) B站水印块（按实测微调，720P 常见 y=26..80）
mask[26:80, 0:245] = 255
# 3) TELEA，radius=8
out = cv2.inpaint(img, mask, inpaintRadius=8, flags=cv2.INPAINT_TELEA)
cv2.imwrite("final.jpg", out, [cv2.IMWRITE_JPEG_QUALITY, 93])
# 验证：水印区 max 应从 ~255 降到 <180；指南针区 mask.sum()==0
```

要点：
- **mask 必须限制在 x<250**。之前用 `mask[0:16,:]=255` 整宽盖顶栏，会把中间指南针一起 inpaint 掉，用户一眼能看出来。
- 只盖水印核心块，不要盲目 dilate 到全图亮像素（会误伤 UI 文字）。
- inpaintRadius=5 对 720P 够用；水印笔画粗可提到 8。
- TELEA 适合 UI 区域的均匀背景；NS 适合有结构延伸的区域。
- 处理完必须打开检查：水印区应与周围纹理连续；小地图、血量、弹药、指南针、赛事 UI 一个都不能少。
- 输出用新文件名（如 `final-a.jpg`），避免和旧结果混淆或读图缓存。
- 不要动右侧赛事信息栏、左下角队伍栏、底部弹药栏、顶部指南针——只动左上角平台水印。

## 图片任务单

写稿前列出每张图要回答的问题：

| 类型 | 必须包含 |
|---|---|
| 赛事连续帧 | 赛事、模式、地图、局数、游戏内时间、队伍/选手、录像来源 |
| 烽火地带路线/站位图 | 真实底图、方向、入口/撤离/交互区、己方分工、敌方来源、放弃条件 |
| 全面战场据点图 | 真实底图、攻防方向、据点、复活链、载具/火力位置、危险侧翼 |
| 决策信息卡 | 触发信号、动作、例外，仅一个核心结论 |
| 选手/战队图片 | 官方身份标识或可交叉核验的图注、拍摄阶段、队伍和来源 |

默认一篇 1500–3500 字复盘使用 3–6 张有信息作用的图片；按证据需要调整，不为凑数放装饰图。

## 连续帧选择

同一波优先选择：

1. **全景/触发帧**：双方位置、目标状态和倒计时可见。
2. **执行帧**：路线、枪线、道具、交互或分工开始发生。
3. **结果帧**：击倒、清场、破译、撤离、占点、票数变化或胜利状态可见。

需要时加一张反例帧。不要从相隔很久的镜头拼成虚假的连续动作。记录精确截帧时间；导播切镜导致信息断裂时在文中说明。

## 标注规范

- 保留一份未标注原图；箭头、编号和文字放在独立 SVG 或其他可编辑标注层。
- 推荐颜色语义：绿色=己方/推荐动作，红色=敌方/危险枪线，黄色=目标/曼德尔砖/交互，蓝色=撤离/安全路线，紫色虚线=仅导播可见的信息。
- 每张图只解释一个问题；编号在正文逐点对应。
- 标注不能遮住小地图、血量/人数、目标计时、击倒信息、资产/票数或比赛水印。
- 图注写明“图片来源：发布者/官方回放”，并标注赛事、地图、局数与游戏内时间。

## 选手与封面

- 指定选手必须用官方选手卡、姓名条、俱乐部图注或同源画面交叉核验身份，不能凭长相猜人。
- 源图优先级：赛事/俱乐部官方直出图 > 官方回放直接截帧 > 可信媒体现场图。默认不用拍摄演播室大屏的畸变画面。
- 封面优先真实赛事舞台、真实选手或关键局内帧；不使用 AI 猜脸或生成“像游戏截图”的画面。
- 用户需要公众号封面时，默认交付可同源裁切的母图、900×383 头图和 500×500 方图；核心人物与信息在两种裁切中都完整。

## 素材与版权台账

每张图记录：文件名、原始链接、发布者、发布日期、赛事/版本、地图/局数/时间、人物身份依据、裁切/标注操作、授权状态和建议署名。

网页公开不代表可商用。正式发布前建议向赛事官方、俱乐部、摄影师或版权方确认授权；Skill 负责记录与提醒，不代替版权方授权。

## 视觉 QA

- 图片是否确属本场比赛或当前版本？
- 选手、队伍、地图、局数和时间是否核验？
- 连续帧是否真的是同一波，而非拼接推断？
- 中文、编号、箭头和图例在手机宽度下是否清楚？
- 标注是否遮挡关键 UI 或制造错误方向？
- 正文是否逐图解释证据、动作和边界？
- 图片是否在相关段落就地出现，没有全部堆在开头或结尾？
- 素材台账是否含原始来源和授权状态？
- 单文件版是否完整内嵌全部本地图片？
